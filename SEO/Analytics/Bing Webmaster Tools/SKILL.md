# Bing Webmaster Tools & IndexNow

## A. Purpose
The Bing Webmaster Tools (BWT) skill establishes the engineering standards for monitoring, diagnosing, and optimizing organic search performance across the Microsoft Bing ecosystem. Bing commands significant, high-converting desktop search market share in affluent enterprise demographics (often exceeding 15-25% of B2B corporate desktop searches due to Windows and Edge enterprise defaults). Furthermore, Bing's search index and graph directly power **Microsoft Copilot**, **ChatGPT web browsing**, and **DuckDuckGo**. This skill provides an operational framework to deploy the **IndexNow protocol** for instant millisecond URL submission, audit Bing crawl stats, and track generative AI visibility across Microsoft's search ecosystem.

## B. Trigger Conditions
Invoke this skill when:
1. Setting up technical search analytics for a newly launched domain or international enterprise brand.
2. Targeting enterprise B2B corporate buyers, government agencies, and desktop users who utilize default Windows/Edge configurations.
3. Implementing the **IndexNow protocol** to achieve instant, automated URL crawling without waiting for asynchronous bot discovery.
4. Monitoring brand recommendations, answers, and source citations generated by Microsoft Copilot.

Upstream dependencies: [Search Console](../Search%20Console/SKILL.md) and [Indexing](../../Technical%20SEO/Indexing/SKILL.md).

## F. Core Concepts and Decision Principles
1. **The IndexNow Paradigm Shift**:
   - Traditional search indexing is *pull-based*: search engines crawl links periodically to discover changes.
   - **IndexNow is push-based**: The instant a page is published, updated, or deleted, your server sends an HTTP POST request containing the URL and an API key to the IndexNow endpoint.
   - Participating search engines (Bing, Yandex, Naver, Seznam) receive the update in **milliseconds**, dispatching crawlers immediately. This reduces server crawl waste and achieves instant indexation.
2. **The Microsoft Copilot Ecosystem Connection**:
   - Microsoft Copilot (formerly Bing Chat) synthesizes real-time web answers directly from the Bing search index.
   - If a page is not indexed or poorly scored in Bing Webmaster Tools, it has **zero probability of being cited by Microsoft Copilot** in Windows, Edge, or Office 365 environments.
3. **Bing's Unique Crawl Control Feature**:
   - Unlike Google (which algorithmically sets crawl rates), Bing Webmaster Tools allows webmasters to **visually configure the hourly crawl rate**:
     - Instruct Bingbot to crawl aggressively at 2:00 AM when your server traffic is low.
     - Restrict Bingbot to minimal requests at 2:00 PM during peak customer checkout hours.

### Step 1: Verify Property via Google Search Console Sync
1. Navigate to Bing Webmaster Tools (`bing.com/webmasters`).
2. Select **"Import from Google Search Console"**.
3. Authorize Google account credentials. Bing will automatically verify all domain properties, import XML sitemaps, and mirror user permissions instantly with zero DNS records required.

### Step 2: Generate and Deploy the IndexNow API Key
1. Generate a random 32-character hexadecimal key (e.g. `e3b0c44298fc1c149afbf4c8996fb924`).
2. Create a plain text file named with the exact key string: `e3b0c44298fc1c149afbf4c8996fb924.txt`.
3. Inside the file, place the exact key string as the only content.
4. Host the file at your domain root:
   `https://example.com/e3b0c44298fc1c149afbf4c8996fb924.txt`
5. Verify access using `curl -I`: It must return HTTP 200 OK with `Content-Type: text/plain`.

### Step 3: Automate IndexNow Submissions via Python / Webhooks
Whenever content is published or updated, trigger an automated POST request:
```python
import requests
import json

def submit_indexnow(url_list):
    api_endpoint = "https://api.indexnow.org/IndexNow"
    host = "example.com"
    key = "e3b0c44298fc1c149afbf4c8996fb924"
    key_location = f"https://{host}/{key}.txt"
    
    payload = {
        "host": host,
        "key": key,
        "keyLocation": key_location,
        "urlList": url_list
    }
    
    headers = {"Content-Type": "application/json; charset=utf-8"}
    resp = requests.post(api_endpoint, data=json.dumps(payload), headers=headers)
    
    if resp.status_code == 200:
        print(f"IndexNow: Successfully submitted {len(url_list)} URLs for instant indexing.")
    elif resp.status_code == 202:
        print("IndexNow: Accepted (Key validation in progress).")
    else:
        print(f"IndexNow Error: HTTP {resp.status_code} - {resp.text}")

# Test submission
submit_indexnow([
    "https://example.com/resources/database-guides/postgresql-backup/",
    "https://example.com/solutions/cloud-security/"
])
```

### Step 4: Configure Hourly Crawl Control
1. In BWT, navigate to **Configuration > Crawl Control**.
2. Select your server's timezone.
3. Review the 24-hour heat map:
   - Increase the crawl slider during off-peak hours (e.g. 01:00 - 05:00 UTC) to allow Bingbot to re-index large catalogs without stressing production databases.
   - Lower the crawl slider during high-traffic business hours.

### Step 5: Audit Bing SEO Reports & Copilot Ingestion
1. Navigate to **Reports > SEO Reports**.
2. Bing automatically runs an automated sitewide crawler that audits for technical compliance:
   - High-priority warnings (Missing H1, missing alt tags, duplicate title tags).
   - Resolve reported issues to maintain high quality scores across Microsoft’s index.
3. Inspect search performance for conversational queries to monitor Copilot source citations.

## L. Failure Modes and Anti-Patterns
- **Ignoring Bing Entirely**: Focusing 100% of efforts on Google and neglecting the 20% of high-net-worth enterprise desktop users searching on Edge and Bing.
- **The Broken Key File**: Returning HTML 404 or a redirect when the IndexNow verification bot checks `example.com/[key].txt`. IndexNow will reject all submitted URLs until the key validates.
- **Submitting Unchanged URLs in Bulk**: Spacing out IndexNow pings only for genuinely new or updated URLs; flooding the API with 100,000 unchanged URLs daily can trigger API rate-limiting.
